# 预生成多尺寸纹理 vs 运行时缩放：策略、预算与淘汰

## 1. 两种策略（配置 `texture_strategy`）

### atlas（预生成多尺寸 / 多级纹理档）
- 源图按 2 的幂边长（128/256/512/1024/2048，可配）预缩放成多档 ARGB8888 纹理。
- 渲染某逻辑尺寸时选「≥目标最大边的最小一档」：多数像素 1:1 或轻微放大，
  每帧 GPU/SDL blit 不做整幅重采样（`src/texcache.c::pick_bucket`）。
- 优点：拖动/旋转/视频墙轮播时单帧成本最低、最稳定（无每帧缩放抖动）。
- 代价：显存 = Σ(档宽×档高×4)；首次切到某档有一次性的 CPU 缩放+上传（miss）。

### runtime（运行时缩放）
- 只保留原图一张纹理，每帧由渲染器缩放到 `content_w×content_h`。
- 优点：显存最省（仅原图一份），无补档冷启动。
- 代价：每帧重采样；软件渲染器（Xvfb/低端终端）上成本显著，大面积动画可能掉帧。

代码：`TEX_ATLAS`/`TEX_RUNTIME` 同一接口 `texcache_get(...)`，可在线热切换
（新图发布或配置保存时重建），策略字段随布局版本入库。

## 2. 预算模型

每条目显存按 `w×h×4` 字节计（ARGB8888，不含驱动对齐，属保守估计）。

```
budget_bytes   默认 32 MiB（配置 budget_bytes_mb）
budget_entries 默认 16 条（配置 budget_entries）
```

约束：`总字节 ≤ budget_bytes` 且 `条数 ≤ budget_entries`。超出即淘汰。

容量规划示例（单张 4K 源图 ARGB8888 ≈ 33 MB，原图本身就在预算外/内要单独评估）：

| 档位        | 单条字节     | 累计（128→2048 六档） |
|-------------|--------------|----------------------|
| 128 长边    | 极少         | ~0.06 MiB            |
| 256         | ~0.26 MiB    | …                    |
| 512         | ~1.0 MiB     |                      |
| 1024        | ~4 MiB       |                      |
| 2048        | ~16 MiB      | 合计 ≈ 21 MiB（在 32 MiB 预算内） |

> 建议：4K 屏终端预算 ≥ 64 MiB；嵌入式 1080p 终端用 runtime 或把 max_bucket 压到 1024。

## 3. 淘汰策略：LRU + 当前帧 pin

- 访问（命中或新建）即刷新 `last_used_tick`，链表头为最近使用。
- 超预算时淘汰「未 pin 中 tick 最小」的条目（`evict_one`）。
- **pin 窗口**：每帧 `texcache_pin_begin` 清零上轮 pin；`texcache_get` 返回的条目标
  pin=1，本轮渲染结束前不被淘汰（防止"正在 blit 的纹理被预算回收导致花屏"）。
- 若所有条目都被 pin（预算极端小、一帧内要用的纹理放不下），本帧不淘汰、宁可短暂超预算，
  下轮 begin 解 pin 后立即回收——绝不释放正在使用的纹理。
- 统计：`hits / misses / evictions / coalesced` 便于现场诊断（可在日志中打印）。

## 4. 失效

- 后台发布新图（`image_rev` 变化）→ `texcache_invalidate_all` 清空所有档位，
  再按新 master 惰性补档；旧图纹理不会被错误复用。
- 预算/档位参数随布局保存生效（在新图或下次 miss 时重建）。

## 5. 与布局版本的关系

纹理策略、预算、档位范围都是**布局配置的一部分**，随版本入库、可撤销（撤销回到会话内
上一个用户版本时纹理参数也回退），但**图片内容版本 image_rev 独立单调递增**：
发布新图只让纹理缓存失效，不改变 fit/focus/strategy 等"用户模式"。
